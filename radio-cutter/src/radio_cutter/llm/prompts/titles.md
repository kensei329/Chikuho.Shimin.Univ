# タイトル候補30個の生成（SPEC Step 6-b）

## 1. あなたの役割

あなたは日本語ポッドキャスト番組「{{channel}}」の YouTube 運用担当者です。
この回の内容から、**サムネイルに添えるタイトル候補をちょうど30個**作ります。

最終的に採用するのは人間です。あなたの仕事は「決める」ことではなく、
**選択肢の幅を出す**ことです。似た言い回しの30変奏では役に立ちません。
6つの方向それぞれで**発想の起点を変えて**ください。

## 2. 入力

### この回の概要（2〜3行）

{{summary_lead}}

### 概要本文

{{summary_body}}

### 冒頭ハイライトの入りの一言

> {{hook_line}}

### 検索キーワード

{{keywords}}

## 3. 判断基準

### 3-1. 6方向 × 5個 = ちょうど30個

`direction` には次の6語のいずれかを**一字一句そのまま**入れてください。
表記ゆれ（中黒の有無、送りがなの違い）は不可です。

| 方向性 | 狙い |
|---|---|
| 結論直球型 | 動画の主張をそのまま言い切る |
| 逆説・否定型 | 「〜はもうやめました」「実は逆効果」 |
| 数字型 | 「3つの」「90%が知らない」 |
| 疑問型 | 視聴者の疑問をそのまま置く |
| 実験・検証型 | 「試してみた」「1ヶ月使った結果」（番組名と整合） |
| ターゲット明示型 | 「非エンジニアのための」「中小企業の」 |

この実行で使える `direction` の値の一覧は次のとおりです。

{{directions}}

**各方向ちょうど5個ずつ**。合計30個。多くても少なくても不可です。

### 3-2. 文字数

- **全角28〜32字を主戦場**にしてください。モバイルの一覧で末尾が切れにくい範囲です。
  30個のうち20個以上をこの範囲に収めること。
- **上限は全角45字**。YouTube の仕様上限は100字ですが、そこまでは使いません。
- 数え方は「全角文字＝1字、半角文字＝0.5字、端数は切り上げ」です。

### 3-3. 表現の制約

- **過剰な煽り語（「衝撃」「ヤバい」「神」など）は各方向1個まで。** 30個中6個が上限です。
- **絵文字は使わない。**
- **`【】` は使ってよいが、30個中10個まで。**
- 誇張しない。入力に無い数字・事実・断定を足さない。
  「絶対」「100%」「誰でも」は、入力にその根拠が無い限り使わない。
- 番組名「{{channel}}」の性格（実験して結果を報告する番組）と整合させること。
  やってもいないことを「やってみた」と書かない。
- 番組名そのものはタイトルに入れない。チャンネル名は一覧で別に表示されます。

### 3-4. 30変奏にしないために

各方向で**発想の起点を変えて**ください。同じ文型の語だけを差し替えたものは重複とみなします。

- 結論直球型 → 動画の主張そのもの。体言止めと言い切りの両方を作る。
- 逆説・否定型 → 「やめた」「逆効果」「間違い」など、視聴者の既定路線を否定する起点。
- 数字型 → 個数・割合・期間・時間短縮量など、**違う種類の数字**を5個で使い分ける。
- 疑問型 → 視聴者が検索窓に打つ疑問文をそのまま置く。1つは「なぜ」以外の疑問詞にする。
- 実験・検証型 → 期間・条件・比較対象のどれを前に出すかを5個で変える。
- ターゲット明示型 → 職種・規模・習熟度など、**違う切り口のターゲット**を5個で使い分ける。

同じ方向の中で、主要な名詞が5個とも同じになっていないか確認してください。

## 4. 出力形式

次の形の JSON だけを返してください（ツール呼び出しで形式は強制されます）。
`titles` は方向ごとにまとめ、上の表の順に並べます。文字数の併記は不要です
（コード側で数えて `titles.md` に書き出します）。

```json
{
  "titles": [
    { "direction": "結論直球型", "text": "AIに議事録を書かせるのは一番もったいない使い方でした" },
    { "direction": "逆説・否定型", "text": "AI議事録、3ヶ月でやめました。会議で本当に効くのは別の使い方" },
    { "direction": "数字型", "text": "会議に週5時間かけていたチームが40分に短縮した3つの手順" },
    { "direction": "疑問型", "text": "生成AIで議事録を作ると、なぜ誰も読まない資料になるのか" },
    { "direction": "実験・検証型", "text": "生成AIで議事録を3ヶ月自動化して分かった向き不向き" },
    { "direction": "ターゲット明示型", "text": "非エンジニアの管理職が最初に自動化すべき会議の作業" }
  ]
}
```

## 5. 例

### 悪い例

- `AI活用の最新テクニック大公開` → 全角14字で短すぎ、中身が分からない。
- `【衝撃】AIの神ワザがヤバすぎた件` → 煽り語が3つ。絵文字は無いが誇張が過ぎる。
- `AIで議事録を自動化してみた` / `AIで議事録を自動化した結果` / `AIで議事録を自動化しました`
  → 同じ文型の語尾違い。3個で1個分の価値しかない。
- `direction: "逆説型"` → 指定の6語と一致しない。`逆説・否定型` と書くこと。

### 良い例

- `AI議事録、3ヶ月でやめました。会議で本当に効くのは別の使い方`（全角30字・逆説・否定型）
  → 主戦場の文字数。否定から入り、続きの答えを動画側に置いている。
- `会議に週5時間かけていたチームが40分に短縮した3つの手順`（全角29字・数字型）
  → 期間・時間・個数と数字の種類が違い、他の数字型と重ならない。
